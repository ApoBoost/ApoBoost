# 【フォーム＆メール】ApoBoost

© 2026 ApoBoost. All rights reserved. このソフトウェアの使用は、ライセンスキーと利用規約に従う場合に限り許諾されます（`LICENSE` を参照）。

問い合わせフォームとメールへの営業送信を自動化するツールです。各自のパソコンにインストールして使います（外部のサーバーは使いません。送信もデータの保存も、そのパソコンの中で行います）。

使い方は、ホームに出る **「はじめの設定」**（6ステップ）に沿って進めてください。くわしい手順とよくある質問は **設定 → ガイド** にあります。

開発する方は `CLAUDE.md` を先に読んでください。

## はじめて使う（インストール）

### かんたんな方法（おすすめ・ターミナル不要）

1. zip を展開する（Windows は zip を右クリック →「すべて展開」。Mac は zip をダブルクリック）
2. できたフォルダを、**ホームの直下**（Mac は「ホーム」＝自分の名前のフォルダ、Windows は `C:\ApoBoost` など）に移す
   - 「ダウンロード」「デスクトップ」「書類」（Mac）や **OneDrive の中**（Windows）に置いたままでも動きますが、パソコンの起動時の自動起動が動かなかったり、部品の用意が失敗しやすかったりします（起動したときに1回だけ案内が出ます）
3. フォルダの中の
   - **Windows**: 「**インストール（最初に1回）.bat**」をダブルクリック（部品の用意からデスクトップのショートカット作成までやります）
   - **Mac**: 「**ApoBoost起動.command**」をダブルクリック（初回は部品の用意から行います。3〜5分）
4. 自動でブラウザが開くので、**管理者のログインIDとパスワードを決める**。「パソコンの起動時に自動で立ち上げる（おすすめ）」は、そのままオンにしておくと、次からパソコンを起動するだけで ApoBoost も動きます
5. そのまま「はじめの設定」が開くので、上から順に進める（フォームだけで送る場合は、メールの手順を「フォームだけで使う（飛ばす）」で飛ばせます）

**Node.js を自分で入れる必要はありません。** パソコンに Node.js が無い・古いときは、起動ファイルが公式の配布元（nodejs.org）から Node.js 22（LTS）を落とし、このフォルダの中（`runtime`）に用意して使います（約50MB。ほかのソフトには影響しません）。
インターネットにつながっていないなどで用意できなかったときは、これまでどおり https://nodejs.org/ が開くので、「LTS」を入れてからもう一度ダブルクリックしてください。
Mac では、フォルダの中の Node.js が古い版のときは起動の際に新しい版へ入れ替えます（取れなければ古い版のまま起動します。ApoBoost が動いている最中は入れ替えません）。

フォーム操作用のブラウザ（Chromium）は、Google Chrome か Microsoft Edge が入っていれば裏で用意し、それまでは Chrome / Edge で送ります（起動を待たせません）。どちらも無いときだけ、用意が終わってから起動します。

2回目からは、デスクトップのショートカット（Windows）／「ApoBoost起動.command」か「ApoBoost.app」（Mac）をダブルクリックするだけです（自動起動をオンにしていれば、それも不要です）。
黒い画面は閉じないでください（閉じると送信も止まります）。すでに起動しているときにもう一度ダブルクリックした場合は、動いている方をブラウザで開くだけです（二重には起動しません）。止めている途中（送信中の会社が終わるのを待っているところ）でダブルクリックした場合は、止まり終わるのを待ってから起動します。

#### 初回に「開けません」と出たとき

**Mac**（「Apple は…検証できませんでした」「開けません」など）

1. 出てきた画面は「完了」（または「OK」）で閉じる
2. **システム設定 → プライバシーとセキュリティ** を開き、下のほうにある「“ApoBoost起動.command”は…ブロックされました」の横の **「このまま開く」** を押す（パスワードか Touch ID を求められます）
3. もう一度ダブルクリックし、確認が出たら「開く」（または「このまま開く」）

macOS 14 以前は、ファイルを右クリック →「開く」→「開く」でも開けます。
「ApoBoost.app」は、ダウンロードしたばかりだと macOS が別の場所に移して開くため、「ApoBoost起動.command から開いてください」と出ます。そのときは「ApoBoost起動.command」から開いてください。

導入する人（販売者）が代わりに入れる場合は、ターミナルで次の1行を実行すると、この確認をまとめて出なくできます（`xattr -dr com.apple.quarantine ` まで入力したあと、展開したフォルダをターミナルの画面にドラッグすると場所が入ります）。

```bash
xattr -dr com.apple.quarantine ~/ApoBoost
```

**Windows**（「Windows によって PC が保護されました」「発行元を確認できませんでした」など）

「詳細情報」→「実行」を押してください（初回だけです）。

**どちらでも**: 「ファイルがそろっていません」と出たら zip を展開せずに開いています。展開してから、展開したフォルダの中のファイルを開いてください。「Node.js を自動で用意できませんでした」のあとに「Node.js が入っていません／古い」と出たら、インターネットにつながっているか確かめてもう一度ダブルクリックするか、https://nodejs.org/ から「LTS」を入れてください。

### これまでの方法（コマンドで操作する）

1. **Node.js 22（LTS）** を入れる → https://nodejs.org/ （「LTS」をダウンロードしてインストール。22・24 なら部品のビルド済みがあるのでそのまま入ります。20・23 などは部品のビルド済みが無く、組み立てに開発ツールが要ることがあります）
2. zip を解凍し、ターミナル（Windows は PowerShell、Mac はターミナル）でそのフォルダに移動
3. 下の3行を順に実行（初回は数分かかります）

```bash
npm install
npx playwright install chromium     # 初回のみ（フォーム操作用のブラウザ本体）
npm start                            # → http://localhost:3210
```

※ `npx playwright install chromium` が「Playwright does not support chromium on mac13」などで失敗する古いOS（macOS 13 以前など）でも、**Google Chrome（または Microsoft Edge）が入っていれば自動でそちらを使う**ので、そのまま `npm start` で使えます。

4. このパソコンのブラウザで http://localhost:3210 を開き、管理者のログインIDとパスワードを決める
5. ホームに出る「はじめの設定」に沿って、送信者の登録 → キャンペーン作成 → リスト取り込み → 開始

止めるときはターミナルで Ctrl+C（送信中の会社があれば、送り終わってから止まります）。データは `data/` フォルダに残ります。

## ログイン

はじめて起動したときは、**このパソコンのブラウザで** http://localhost:3210 を開くと「管理者のログインIDとパスワードを決める」画面が出ます。決めるとそのままログインした状態になり、次回からはそのID・パスワードでログインします。

- この画面は、ApoBoost を起動したパソコン自身から開いたときだけ出ます（同じWi-Fiの他の人に先に管理者を取られないようにするため）。他のパソコンから開くと、ログイン画面に案内が出ます
- メンバーのアカウントは「ユーザー管理」から発行できます（一般ユーザーには自分のデータだけが見えます）

画面を使わずに最初の管理者を作りたい場合（まとめて設定する場合など）は、初回起動時だけ環境変数で指定できます。この場合はターミナルにアカウントが表示されます:

```bash
ADMIN_USER=admin ADMIN_PASSWORD=好きなパスワード npm start
```

同じログインIDで15分に5回パスワードを間違えると、しばらくログインできなくなります。

## 使う前に知っておいてほしいこと

- **メールの送りすぎに注意**：短時間に大量に送ると、Gmail のアカウントが一時停止されます。作ったばかりのアカウントは1日50〜100通から始め、日中に少しずつ送ってください。停止やログイン拒否を検知すると、ApoBoostはメール送信を自動で一時停止します（残りの会社は「待機」のまま）。
- **営業メールの法律上の表示**：特定電子メール法により、営業メールには送信者の名称・住所・配信停止の連絡先の表示が必要です。送信者の住所が未登録だとメールは送られません。メールの末尾には「メール配信停止」リンクが自動で入ります。
- **受信箱の読み取りと振り分け**：送信者プロフィールで「受信箱を読んで…」をオンにすると（初期値オン）、送信用メールの受信箱を15分ごとに読み、送った会社からの返信（返信あり／アポ／断り）と届かなかったメールを自動で記録します。「受信箱を自動で振り分ける」（初期値オン）にすると、フォームに送った会社からの「お問い合わせありがとうございます」等の自動返信と、届かなかったメールを、ラベル「ApoBoost/自動返信」「ApoBoost/届かなかった」に移して受信箱から外します。アポの返信にはラベル「ApoBoost/アポ」とスターを付けます。営業と関係のないメール・社内のメール・契約やセキュリティの知らせには触りません。消すことはしません。アポだけを見るには、上のメニューの「アポ」を開いてください。
- **パソコンのスリープ**：送信はこのパソコンの中で動くため、スリープ・ふたを閉じる・アプリの終了で止まります（起動すると続きから再開）。
- **他のパソコンから開く**：同じWi-Fi・社内ネットワークの人は、「ユーザー管理」に表示されるURLで開けます。アドレス欄の localhost のリンクは他のパソコンでは開けません。カフェ等の共用Wi-Fiでは、同じネットワークの他人からもログイン画面が見える点に注意してください。
- **パスワード類の保存**：Gmail のアプリパスワードと AI の APIキーは、このパソコンの `data/` 内に保存されます（暗号化はしていません）。共用パソコンでは使わないでください。
- **除外リストはパソコンごと**：別のメンバーのApoBoostとは共有されません。チームで使う場合は、断りの会社を定期的に共有してください。
- **初期文面**：新しいキャンペーンの本文・件名には【ここに…】の書き換え箇所があり、書き換えないと送信できません。

## AI の設定（任意）

テンプレートでの送信は無料で、AI は不要です。AI で文面を個別化する場合は、**画面の「設定」から APIキーを登録**します（管理者のみ）。料金の目安・取得手順も設定画面に書いてあります。キーはこのパソコンの `data/` 内にだけ保存されます。

環境変数でも渡せます（設定画面が優先）:

```bash
ANTHROPIC_API_KEY=sk-... npm start     # Claude
GEMINI_API_KEY=...       npm start     # Gemini
```

## 画面の案内

上のメニューは5つです。

- **ホーム** … 今日の進み具合、アポ、要対応、次にやること。最初は「はじめの設定」への案内が出ます
- **キャンペーン** … 一覧と作成（3ステップ）。キャンペーンの中は「① 準備／② 送信／③ 結果」の3タブ
- **要対応** … 自動で送れなかった会社。「今日やる10件」と「同じ原因のまとめ」から片づけます。画像認証の会社は「続けて処理する」で1社ずつ
- **成果** … 日別・月別の送信数、業種別／都道府県別／時間帯別の反応率、送れなかった理由、週次レポート
- **設定** … 基本設定／送信者／除外・チーム共有／動作チェック・バックアップ／アップデート／ユーザー／ガイド（上のタブで切り替え）

困ったときは **設定 → 動作チェック・バックアップ** を開き、解決しなければ「診断ファイル」を配布元に送ってください。
導入時に渡す資料は **/checklist**（導入チェックリスト。印刷・PDF保存できます）。

## チームで使う

- **除外リストの共有**（取り込み）… Googleスプレッドシートを1つ決めて、全員が同じURLを登録（1日1回自動）
- **送信済み・除外の双方向共有**… 「除外リスト」画面の「チームで共有する」に、読み取り用のシートURLと、書き込み用の Apps Script URL を登録すると、
  誰かが送った会社には他のメンバーが送らなくなります（取り込み時と送信直前に確認）。Apps Script のコードは画面からコピーできます

## ライセンス・利用規約

**ライセンスキーが必要です。** キーが無くても、初めて起動してから14日間（お試し期間）は使えます。そのあとは、キーを登録するまで送信が止まります（設定で外すことはできません）。
キーには「使用を許諾した会社名・台数・期限」が入っていて、許諾した会社名は各画面の下とログイン画面に表示されます。

使う前に、管理者が「利用規約」（画面の下のリンク、または `/terms`）に同意します。無断の複製・再配布・転売・解析は、利用規約で禁じています。

### キーの発行（配布元の作業）

```bash
npm run license -- --to "株式会社サンプル" --days 365 --seats 3  # キーを発行して相手に渡す（期限なしにしたいときは --days 3650 など）
```

出てきた `APO1.…` の1行を、相手の 設定 → ライセンス に貼ってもらいます。秘密鍵（`license-keys/private.pem`）は配布元のPCにだけ置き、無くさないようにバックアップしてください。

## 守っていること

- 「営業お断り」文言を検知したらスキップし、そのドメインを除外リストに自動登録（キャンペーン設定で「送る」に変更可・非推奨）
- 目に見える CAPTCHA（reCAPTCHA v2 / hCaptcha / Turnstile / 画像認証）があればスキップ。突破はしない
- 同じ会社には再送禁止期間（既定90日・キャンペーンごとに変更可）は再送しない（全キャンペーン横断）。グループにしたキャンペーン同士でも重ねて送らない
- 官公庁・自治体・学校のドメインは既定で除外
- 送ったか判断できなかった会社は「失敗（要確認）」にして、自動では送り直さない（二重送信を防ぐため）
- 配信停止・断りの返信・宛先不明で戻ってきたアドレスには、以後送らない
- 送信結果はスクリーンショット付きで保存

## 更新版を配る（配布元の作業）

このリポジトリが開発の正であり、配布元でもあります。配布した各PCは
`https://raw.githubusercontent.com/ApoBoost/ApoBoost/main/release.json` を見に来ます。

**更新版を出す手順**

```bash
git pull                              # 先に他の人の変更を取り込む
npx tsc --noEmit && npm test          # 型チェックと送信の通しテスト
npm version patch                     # 0.3.1 → 0.3.2
npm run release -- "直した内容を一言"    # release.json を書き出す（この文言が利用者の画面に出ます）
git add -A && git commit -m "ApoBoost v0.3.2" && git push
```

**先行版として出す**こともできます（自分たちのPCだけで先に試し、問題がなければ安定版にする）。

```bash
npm run release -- --beta "試したい変更"   # 先行版（アップデート画面で「先行版」を選んだ端末にだけ届く）
npm run release -- "問題なかったので全員へ" # 安定版（全端末に届く）
```

`git push` はこの1回だけです。これで各PCの「アップデート」画面に新しい版が出ます。

**バージョンを上げずに push した場合**は、コードはGitHubに入りますが誰にも配られません。
開発中の細かい修正はそれでよく、区切りがついたところでリリースする、という使い分けで構いません。

配布元を変える場合は `update.json` の `manifest_url` を書き換えてから配り直してください。

src/app/context.ts   どの経路からも使う共通の道具（権限・お知らせ・集計など）
src/app/background.ts 裏で動く仕事（自動バックアップ・自動更新・返信確認・共有の同期・再開・終了処理）
src/routes/*.ts      画面ごとの経路（auth / campaigns / jobs / todo / senders / lists / settings / pages）
src/ui/*.ts          画面のHTML（layout / styles / home / campaign / job / todo / senders / settings / stats / onboarding …）
src/views.ts         src/ui をまとめて再輸出するだけ
src/settings.ts      設定キーと既定値の一覧
src/db.ts            テーブル定義とマイグレーション
src/csv.ts           CSV取り込み（列名の別名対応・振り分け）
src/formFinder.ts    フォームページ探索（URL → サイト内リンク → よくあるパス → サイトマップ）
src/formFiller.ts    項目の判定と入力・確認画面・送信・結果判定
src/detect.ts        営業お断り・CAPTCHA 検知
src/engine.ts        1社分の送信フロー（Playwright）
src/message.ts       文面生成（テンプレ差し込み / AI / A/B / 件名の使い分け / AIの上限）
src/templates.ts     業種別の文面ひな形
src/email.ts         メール送信（SMTP）・配信停止・送信の一時停止
src/replies.ts       受信箱の読み取り（返信の自動判定・学習・戻りメール）
src/worker.ts        キュー処理（時間帯・上限・ウォームアップ・アカウント切替・停止）
src/share.ts         チームでの共有（送信済み・除外の双方向）
src/license.ts       ライセンスの検証
src/health.ts / backup.ts / applog.ts / awake.ts / autostart.ts / notify.ts / jp.ts
                     動作チェック・バックアップ・エラーログ・スリープ抑止・自動起動・通知・エラーの日本語化
src/auth.ts          ログイン・ユーザー管理
src/update.ts        配布後の自動アップデート（安定版／先行版）
scripts/             起動役・release.json 生成・ライセンス発行
test/unit.ts         部品の単体テスト（数秒）
test/replies.ts      返信判定・戻りメール検知のテスト
test/smoke.ts        全画面が開けるかの確認（20秒ほど）

`npm run test:quick` は型チェック＋単体＋画面の確認だけ（1分以内）。`npm test` は通しテストまで全部。
